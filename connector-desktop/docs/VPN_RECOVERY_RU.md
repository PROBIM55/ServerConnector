# Восстановление старого VPN — 13 октября 2026

## Подтверждённый сбой

После дисковых задержек VPS и штатной перезагрузки у интерфейса `awgserver`
сбросились WeakHostSend/WeakHostReceive. Их восстановление вернуло прежний
сетевой путь. На SHMIGELSKAYADS служба `AmneziaWGTunnel$structura-vpn`
оставалась запущенной, но VPN не передавал рабочий трафик. Сервер получал
инициации handshake и отправлял ответы; пересоздание peer на сервере не помогло.
После локального Restart-Service восстановились handshake, heartbeat и SMB.
Точный внутренний механизм зависания AmneziaWG не установлен.

В клиенте также найдены два дефекта: «Переподключить VPN» при неизменном
конфиге возвращало успех без перезапуска, а зелёный статус основывался только
на состоянии службы. Исправления находятся в исходниках следующего выпуска;
установленные версии 1.0.31 и ниже этим пакетом не заменяются.

## Пакет для установленных клиентов

`Structura.VpnRecovery.Setup.exe` устанавливает отдельную задачу Windows.
Пользователь один раз открывает EXE и подтверждает UAC с правами администратора.
Коннектор, ключи, настройки VPN, учётные данные и модели не заменяются.
Сама установка не перезапускает VPN и не требует перезагрузки ПК.

Ссылка на опубликованный пакет:
https://server.structura-most.ru/updates/files/Structura.VpnRecovery.Setup-20261013.exe

SHA-256: `a500882a4bc0b007c7149ebbadc5bdc6b5dee0aafb7d7d620a77b99b555fb842`.
Отдельный файл `.sha256` находится рядом с EXE.
Пакет не имеет подписи Authenticode; SHA-256 подтверждает только совпадение файла.
Если зависший VPN блокирует доступ к этому адресу, передайте уже скачанный EXE
через доступный сотруднику канал.

Задача `StructuraConnectorVpnRecoveryClient` работает под SYSTEM при старте
Windows и раз в минуту, независимо от открытого приложения. Скрипт и состояние
хранятся в `%ProgramData%\StructuraConnectorVpnRecovery`; менять их могут только
SYSTEM и Administrators. Задача управляет только фиксированной VPN-службой.

Условия автоматического восстановления:

- Служба существует, включён автоматический запуск, нет установки MSI.
- Есть маршрут по умолчанию вне собственного VPN.
- Три проверки подряд не подтверждают TCP 445 или 443 на `10.77.123.1`.
- Нет Established SMB-соединения к `62.113.36.107` или `10.77.123.1`, в том
  числе зависшего соединения, которое может содержать незавершённые записи.
- Прошло не менее 180 секунд после старта службы; повторное вмешательство
  допускается не чаще одного раза за 15 минут, даже если попытка не удалась.

Перед перезапуском SMB и доступность сервера проверяются повторно. Если связь
восстановилась, служба остаётся работающей. Остановленная автоматическая служба
запускается после защитной задержки; отключённую службу монитор не включает.
Это защита от повторения данного симптома, а не восстановление повреждённых RVT.

## Серверная защита

`StructuraConnectorVpnRecoveryServer` установлена на VPS. Раз в минуту и при
старте Windows она проверяет ожидаемые интерфейсы/IP и возвращает Enabled для
WeakHostSend/WeakHostReceive в ActiveStore и PersistentStore, только если они
сбросились. Службы, peer, firewall, SMB-права и модели не меняет.

После установки: задача завершилась с кодом 0, VPN-процесс сохранил PID 2672,
действующие SMB-сеансы продолжили работу. Перезагрузка для проверки не проводилась.
Legacy manifest 1.0.31 сохранён побайтно: SHA-256
`44d312f14992f533113def5e5b1cb9dd61251b705b190577ec22f2cfb27456f8`.

## Проверка и откат

В планировщике Windows проверить наличие задачи и результат последнего запуска
0; затем проверить подключение Connector и открытие общей папки. Не следует
искусственно ронять VPN или перезагружать сервер во время работы с моделями.
Факт появления задачи не доказывает, что восстановление уже понадобилось.
Файл `client-state.json` содержит счётчики, `recovery.log` — попытки восстановления.

Откат клиента: запустить тот же EXE с аргументом `/uninstall` либо удалить только
задачу `StructuraConnectorVpnRecoveryClient` в планировщике. VPN остаётся установлен.
Защищённые файлы и маркер сохраняются для диагностики и предотвращения повторной
автоустановки из приложения. Повторный запуск EXE без аргументов устанавливает задачу.
Откат серверной защиты — удалить только `StructuraConnectorVpnRecoveryServer`;
рабочие сетевые параметры при этом не сбрасываются.

Сборка: `powershell.exe -NoProfile -ExecutionPolicy Bypass -File
scripts/build_vpn_recovery_setup.ps1 -OutputDirectory <каталог>`.
Проверки: Release WPF — 0 ошибок/предупреждений; Desktop — 192 passed, 1 skipped;
12 защитных условий PowerShell, проверка нового SMB-соединения перед действием,
read-only/idempotency сервера. Ресурсы EXE и требование UAC сверены; публичное
скачивание вернуло HTTP 200, доверенный TLS и совпавший SHA-256.
Пользователь подтвердил сообщение об успешной установке на SHMIGELSKAYADS.
Повторный сбой с автоматическим восстановлением вживую не воспроизводился;
массовое распространение на остальные ПК пока не подтверждено.
