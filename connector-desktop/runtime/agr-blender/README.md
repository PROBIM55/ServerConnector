# Вычислительный обработчик публикации АГР

`agr_worker.py` — локальный вычислительный сценарий Platform для построения НПМ
и ВПМ. Его запускает `Platform.Connector.Compute.Agr` закреплённой управляемой
portable-сборкой Blender **5.2.0 LTS** без интерфейса. Пользователю не требуется
вручную устанавливать, открывать Blender или обмениваться промежуточными
файлами.

## Запуск

```powershell
blender.exe --background --factory-startup --disable-autoexec --python agr_worker.py -- --preflight
blender.exe --background --factory-startup --disable-autoexec --python agr_worker.py -- --manifest <путь-к-manifest.json>
```

Сценарий читает контракты:

- `shared/contracts/modules/agr-publication/publication-build-manifest-v1.schema.json`;
- `shared/contracts/modules/agr-publication/publication-mesh-package-v1.schema.json`.

Пути в манифесте могут быть только относительными и не должны выходить за
рабочий каталог задания. Двоичные буферы проверяются по размеру и SHA-256.
Прогресс и итог выдаются в stdout однострочными JSON-сообщениями с префиксами
`AGR_PROGRESS` и `AGR_RESULT`.

## Реализованный срез 0.1

- импорт треугольных мешей, UV, материалов и текстур из внутреннего пакета;
- перевод миллиметров в метры и осей Y-up/Z-up;
- применение матриц, пересчёт нормалей, триангуляция и общее упрощение;
- сохранение идентификаторов сцены и модулей в свойствах FBX;
- выпуск НПМ по ролям `Ground`/`OKS` или единого файла;
- бинарный FBX 7.4/2014 штатным экспортёром Blender;
- проверка заголовка, контрольной суммы и инвентаря;
- повторное открытие каждого FBX в чистой сцене и проверка свойств.

Срез намеренно завершает задание ошибкой, если запрошены ещё не реализованные
операции: объединение мешей, сварка с ненулевым допуском, выпуск GeoJSON или
режим текстуринга, отличный от `preserve`. Молчаливой подмены результата
упрощённой логикой нет. Worker также отказывается работать с версией Blender,
отличной от 5.2.0: обновление runtime выполняется только вместе с регрессией и
новой версией worker.

## Развёртывание

Blender не включается в git и MSI. Connector Desktop скачивает официальный
Windows x64 ZIP по закреплённому runtime manifest, проверяет размер и SHA-256,
безопасно распаковывает его в `%LOCALAPPDATA%\Platform\Runtimes\Blender\5.2.0`
и включает только после успешного preflight. Worker входит в publish коннектора
как доверенный версионированный компонент и никогда не загружается из задания.

Стартовая политика — один локальный Blender-процесс, пониженный приоритет и
отдельный рабочий каталог на выпуск. Увеличение параллелизма допускается только
после проверки памяти, диска и времени на контрольной модели ШЗЭ длиной 1,8 км.

Локальная проверка:

```powershell
scripts/local/verify_agr_blender_worker.ps1 -BlenderPath <путь-к-blender.exe>
```

Она строит два тестовых объекта, получает два FBX, проверяет версию 7400 и
повторно открывает файлы через независимую чистую сцену Blender.
