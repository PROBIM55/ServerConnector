# SMB helper: граница проверки ACL

Перед созданием/изменением локальной учётной записи runner проверяет DACL каждой
настроенной SMB-share. Разрешены ACE только для `SYSTEM`, локальной группы
Administrators и SID, который `Get-LocalUser -SID` подтверждает как отдельную
локальную учётную запись. Широкие и групповые Allow ACE, локальные группы,
неразрешённые SID, неподдерживаемые ACE и отсутствующий DACL останавливают
команду до ACL- или user-изменений. Существующие индивидуальные legacy ACE
сохраняются.

Управляемая учётная запись не должна быть прямым или вложенным участником
локальной группы Administrators: такой токен может получить полный доступ по
администраторскому ACE share. При неизвестном результате проверки операция
завершается fail-closed; членство автоматически не меняется.

`shareAccess` и `ntfsAccess` в ответе остаются readback-записями точечных ACE
управляемого SID. Они подтверждают наличие или отсутствие этих записей и не
являются расчётом эффективных прав пользователя. Для SMB сетевую границу задаёт
также share DACL; NTFS-права вне этой share отдельно не подтверждаются.

Каждый будущий ограниченный ресурс должен иметь собственную share и корень,
согласованные с ней. Не моделируйте несколько независимо ограниченных ресурсов
как виртуальные права внутри одной общей share/root. Существующие широкие
унаследованные NTFS ACE требуют отдельного проектирования чистого resource-root;
этот helper их не сбрасывает и не переписывает.

Узкая регрессия guard:

```powershell
powershell.exe -NoProfile -File .\smb-helper\tests\ShareBoundaryGuard.Tests.ps1
```

## Учетная запись только для SMB

Перед выдачей или изменением пароля существующей управляемой записи helper
проверяет эффективную политику запущенной Windows-службы OpenSSH через
`sshd -T -C user=<имя>,host=localhost,addr=127.0.0.1`. Проверяются стандартный
бинарный файл и стандартный `ProgramData\ssh\sshd_config`, отсутствие `Include`,
наличие явного `DenyUsers` для точного имени и запуск службы позже изменения
конфигурации. Неоднозначная конфигурация и недоступная проверка останавливают
операцию до пароля и ACL.

Для точного SID управляемой локальной записи через LSA назначаются и читаются
обратно `SeDenyInteractiveLogonRight` и `SeDenyRemoteInteractiveLogonRight`.
Остальные права записи сохраняются; сетевой вход `SeDenyNetworkLogonRight` не
запрещается, поэтому SMB остается доступен. Новая запись создается отключенной
и включается только после проверки SSH-политики, чтения прав LSA и настройки
точечных ACL.

Узкая регрессия service identity (без вызова live LSA):

```powershell
powershell.exe -NoProfile -File .\smb-helper\tests\SmbServiceIdentity.Tests.ps1
```
